## Current evidence boundary

The public repository establishes fixture-level evidence. It does not establish live Alibaba Cloud execution, customer traction, measured percentage improvements, production readiness, or revenue outcomes.

This boundary is intentional. It protects the application from overclaiming while making the next validation steps explicit.

## Maximum-strength principle

The strongest grant submission is not the one with the largest claims. It is the one where every material claim can be traced to:

1. a concrete artifact,
2. a reproducible procedure,
3. an official external source, or
4. an explicitly labeled hypothesis.

## Remaining external dependency

The following cannot be created truthfully by repository editing and must come from real-world execution or official account/program records:

- eligibility of a private individual under the current program terms,
- exact approved credit/token allocation,
- live Alibaba Cloud service availability and region,
- actual Alpha 0.4 execution output from the implementation,
- customer/pilot participation,
- measured KPI improvements,
- production workload consumption.
